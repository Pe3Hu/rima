# Шаг 11. Тестирование и критерии приёмки

**Цель.** Проверить, что фронт работ выполнен и все сущности работают
по описанной логике.

**Зависит от.** Шаги 1–10.

## Ручные сценарии

### Сценарий 1. Старт Forge

- Открывается `forge/forge.tscn` (главная сцена сейчас).
- Заголовок «Текущее оружие: <name>».
- Левая Mold = актуальный Mold оружия (12 Ingot'ов, толщины из стартового
  решения `out/<weapon>.json` + Warehouse).
- Центральная Mold сгенерирована из `out/<weapon>.json` (решение ≠ левому).
- Правая Mold = сумма левой и центральной.
- `%FusionButton` активна.

### Сценарий 2. Выбор Piece

- ЛКМ по Piece центра → подсвечен весь Ingot (все его клетки).
- Повторный ЛКМ — снятие выбора.
- ЛКМ по пустой клетке — снятие выбора.

### Сценарий 3. Смена варианта

- `A` — предыдущий вариант Ingot'а из Warehouse той же формы.
- `D` — следующий.
- При смене варианта `origin`/`rotation`/`flip` сохраняются.
- Правая Mold пересчитана.

### Сценарий 4. Формула правой Mold

- `right.thicknesses[i] = left.thicknesses[i] + center_thickness` по клеткам.
- В `right` ровно 12 Ingot'ов, все клетки покрыты.

### Сценарий 5. Fusion

- Нажать Fusion: `weapon.mold := right`, из Warehouse списаны 12 Ingot'ов
  центра, центр пересобран, левая = бывшая правая.
- Правая = новая левая + новый центр.
- Если какая-то форма в Warehouse обнулилась — Fusion учитывает это
  (по решению в `notes.md`).
- Fusion при пустом центре — не происходит.

### Сценарий 6. Имена файлов

- `tasks/` содержит файлы вида `<weapon>.json`, а не `board_xxx.json`.
- `out/` содержит файлы вида `<weapon>.json`.
- Солвер и тесты используют новые пути.

### Сценарий 7. Удаление старых сущностей

- `entities/hull/hull.gd`, `hull.tscn`, `module/*`, `forge/board/*` удалены.
- `Mother.hull` отсутствует.
- Упоминаний `Hull`, `Module`, `Capsule`, `Board*` (кроме `MaskBoardData`)
  в коде нет.
- `Q`/`E` в проекте не обрабатываются.

### Сценарий 8. Правила

- Нет общих папок `scripts/`, `scenes/`, `datas/`, `components/`.
- `class_name` = имя файла.
- `*Data` — `RefCounted`, кроме `ShapeData` (согласованное исключение).
- Корневые data — только `Mother`.
- `Catalog` — числа/списки. `Digest` — таблицы. `Bozo` — enum.
- Случайность — только `Helper.rng`.
- Новых автозагрузок нет.

## Автоматические проверки (по возможности)

- `WarehouseData.get_total_count() == 36` после старта.
- После каждого `apply_removal` счётчик уменьшается на 1.
- `MoldData.get_thickness_map()` для правой = сумма левой и центральной
  по каждой клетке.
- `MoldData.ingots.size() == 12` для всех трёх Mold.
- `IngotData.get_world_cells().size() == 5` для всех Ingot'ов.

## Что зафиксировать в `notes.md`

- Поведение повторного ЛКМ (снимать / не снимать).
- Порядок `origin`/`rotation`/`flip` и как они копируются при смене варианта.
- Что делать при исчерпании формы в Warehouse (Fusion блокируется /
  пересбор центра без этой формы / иное).
- Что делать, если в `out/<weapon>.json` только одно решение — тогда
  «отличное от левого» невозможно. По умолчанию — использовать его же
  и зафиксировать ограничение.
- `MaskBoardData` не переименовывался — оставлен как внутренний класс
  солвера.
  
  ## Решения по переработке Forge (после шага 6)

- Hull, Module, Capsule удалены полностью. Board* (от агента) удалены.
- Введены WeaponData, MoldData, PieceData (все RefCounted) и сцены
  Mold, Piece.

  Mother.current_weapon_index. Стартовый — chokuto (index 0).

  variant_index у правых = -1.
- Fusion: weapon.mold := right, из Warehouse списываются 12 Ingot'ов
  центра, центр пересобирается, левая = новая weapon.mold.

- Q/E удалены из проекта.

  (offset cell_size * 0.5). Размер клетки — Catalog.MOLD_CELL_SIZE.
- `MaskBoardData` (солвер) не переименовывался — внутренний класс,
  не виден в игре.
- `variant_index` добавлен в IngotData (расширение шага 3).
